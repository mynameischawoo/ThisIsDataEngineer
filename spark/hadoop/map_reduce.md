## Hadoop - MapReduce
> Spark 학습 과정에서 함께 공부한 Hadoop MapReduce 개념을 요약한다.

## What is MapReduce?
- **MapReduce**는 대용량 데이터 처리를 위한 **프로그래밍 모델**이자 **프레임워크**이다.  
- 프레임워크 자체는 현재 많이 쓰이지 않지만, 모델 개념은 여전히 여러 시스템에서 활용되고 있어 이해할 필요가 있다.  

## Problem Statement
- 예: 20TB CSV 파일의 라인 수를 세는 경우  

### 단순 접근 방법
1. 파일 전체를 메모리에 올림  
2. 한 줄씩 반복문으로 읽어 카운트  
3. 최종적으로 라인 수 계산  
- 하지만 **20TB를 단일 머신에서 처리하는 것은 비현실적**이고, HDD 성능 제약으로 처리 시간이 매우 길다.  

### MapReduce 접근 방법
- HDFS에 20TB 파일을 **128MB 블록 단위**로 분산 저장  
- **Map 함수**: 각 블록의 라인 수를 계산 (병렬 실행)  
- **Reduce 함수**: 모든 블록의 카운트를 합산  
- 결과적으로 **대용량 데이터를 빠르고 안전하게 처리**할 수 있다.  

## Background of Apache Hive
- Hadoop MapReduce는 강력하지만 **개발 난이도와 유지보수 부담**이 크다.  
- 이를 보완하기 위해 **SQL 기반으로 MapReduce 작업을 실행할 수 있는 Hive**가 등장했다.  
- Hive는 **SQL 쿼리를 MapReduce로 자동 변환**해 Java 코드를 직접 작성할 필요가 없다.  

## Limitations of Apache Hive

| Point | Desc |
|------|------|
| **실시간 처리 한계** | Hive는 배치 중심으로 설계되어 있어 실시간 쿼리/저지연 분석에는 부적합하다. |
| **속도** | MapReduce 기반 실행으로 쿼리 속도가 느리고, 대화형 분석에 비효율적이다. |
| **트랜잭션 제약** | 완전한 ACID 트랜잭션 지원이 늦게 도입되었고, 여전히 RDBMS 수준에는 미치지 못한다. |
| **복잡한 조인 처리** | 대규모 테이블 조인 시 성능이 크게 저하될 수 있다. |
| **업데이트/삭제 한계** | 기본적으로 Append-Only 구조라 데이터 수정/삭제가 비효율적이다. |
| **의존성** | Hadoop/HDFS와 YARN 같은 에코시스템에 강하게 의존한다. |
| **리소스 사용량** | 쿼리 실행 시 많은 CPU/메모리 자원을 소모할 수 있다. |
